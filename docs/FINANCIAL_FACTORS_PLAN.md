# 财务因子扩展方案：从接口可读到可核对的历史特征

状态：**设计提案，尚未实施**。核对日期：2026-10-08。本轮只读仓库与官方文档，没有新增 Tushare 数据调用、付费请求或批量抓取，也没有修改引擎。本文中的候选字段、公式和验收条件不代表它们已经拥有完整历史数据，更不代表有预测优势。

## 1. 已有能力与实际缺口

当前 `engine/atlas_quant/connectors.py` 登记 21 个 `fina_indicator` 字段；`research_registry.py` 将它们生成为 21 个已知值、42 个交易日变化和 3 个每股指标/价格比，共 **66 个财务配方定义**。20/60 日变化是已知值的交易日变化，不是季度同比；每股指标也没有自动变成 TTM。

| 层次 | 当前证据 | 尚不能推出的结论 |
| --- | --- | --- |
| 接口访问 | `docs/DATA_SOURCES.md` 与 `docs/DATA.md` 记录 `income`、`balancesheet`、`cashflow` 已通过真实读取；本轮没有重放这些请求 | 全市场、全历史、所有字段均有值 |
| 自动研究连接 | 只有 21 个 `fd_` 指标能由 `load_financial_history` 请求并自动公告时点对齐 | 三张报表已经进入全部因子或 F 模型 |
| 时点处理 | 公告日后首个官方交易日生效；旧报告期的迟到修订不替换较新报告期；同日同字段冲突隔离为 null | 供应商完整保留了所有最初发布版本 |
| 数据来源 | 来源、字段路径、逐行可用日期、快照哈希与冲突计数可记录 | Tushare 返回值本身等同于已经核验的公司原始披露 |

`FD` 是现有接口兼容键，不应成为第五个逻辑数据库。扩展仍遵守 PCD / MKT / EXT / MODEL：供应商适配与外部研究数据保留其来源边界，派生模型值不得覆盖 PCD 原始公司披露或其他原值。

## 2. 官方接口差异必须进入适配器合同

三张报表均有报告期、公告日期和报表类型；合并、母公司、单季度与调整记录的口径不同，不能把返回行简单拼接后取最后一行。利润表还把公告日期与实际公告日期分别列出。按单股历史接口做有限范围读取，不假定存在季度全市场 VIP 权限。[利润表官方文档](https://tushare.pro/document/2?doc_id=33)

资产负债表是时点存量。其股本字段注明“股”，不能与其他接口里的“万股”无换算混用。当前主金额字段的官方表格并非每项都明确写出币种和单位，因此需要逐字段的单位证据；不能仅因数值看起来合理就宣布已经统一成 CNY。[资产负债表官方文档](https://tushare.pro/document/2?doc_id=36)

现金流量表的 `update_flag` 标记当前更新状态，并不是可用于回测的披露时间。接口还存在 `is_calc` 等参数差异，若未来接入，必须记录返回的是哪种计算口径，不能静默替换默认口径。[现金流量表官方文档](https://tushare.pro/document/2?doc_id=44)

当前官方 `fina_indicator` 文档把日期范围描述为报告期范围，并给出单次 100 条限制；三张报表把日期范围描述为公告日范围。下一版不能把同一个日期切片函数无差别套用到所有接口。`fina_indicator.update_flag` 可作为原始元数据保存，但也不构成历史版本证明。[财务指标官方文档](https://tushare.pro/document/2?doc_id=79)

**这项日期差异不是已发现的当前加载 bug。** 本轮用按 `end_date` 报告期过滤的内存客户端调用真实 `load_financial_history` 和 `join_financial_asof`：研究窗 2023-01-01 至 2024-09-30，两个请求覆盖 2021-01-01 至 2024-09-30 的报告期。2022 年报在 2023-04-28 公告能被取到，直到 2023-05-04 才可用；2023Q1 在 05-05 公告，到 05-08 才替换；05-08 的旧年报修订不覆盖 Q1。2024Q3 虽在报告期筛选内，但 10-30 公告，未进入任何研究日。模拟截断后按报告期拆片，结果与未截断版本完全相同。没有供应商调用。

因此现有代码的“按报告期有限取回，再按公告日 join”逻辑在该边界核对中正确，无需为参数名称改引擎。两年预取是明确的有限覆盖，不保证取得报告期早于该边界的极晚公告；例如只有 2020 年报在 2023 年迟到披露时，2021 年起的预取不会取到它。这是有界覆盖反例，不是公告日期被误用或未来数据泄漏；如未来支持这类历史，应以显式覆盖/追加请求预算解决，不能无界回溯。本提案的警示针对新三表适配器共享代码时的合同设计。

已有代码需要后续实施的具体差异：

- `EXTRA_DATASETS` 已登记三张表的少量字段，但 `FINANCIAL_ALIASES` 与自动加载仍只接受指标表。保留旧别名与旧快照语义。
- 三表当前字段列表没有 `end_type`；参数白名单没有 `f_ann_date`。先逐接口验证支持范围，再增加白名单和严格类型校验，不能直接开放任意参数。
- 当前 `report_type` / `comp_type` 是字符串范围验证，需补已登记枚举及配方适用范围。
- `scripts/seed-registry.mjs` 的财务字段单位还是 `source_native`；未来应从同一字段注册表生成引擎与目录元数据，避免前端单位和计算单位分叉。

## 3. 字段与版本模型

建议先统一字段合同，再扩公式。每个原始字段登记：`endpoint`、`providerField`、`alias`、`dataType`、`nativeUnit`、`canonicalUnit`、`scale`、`unitEvidence`、`periodKind`、`statementScope`、`companyTypes`、`nullPolicy`、`mappingVersion`。单位未核实使用 `unverified_source_unit`，需要金额换算的配方不可运行。

原始记录另外保存证券身份、报告期、报表类型、公司类型、公告日、实际公告日、更新标记、抓取时间、请求参数、原始内容哈希和不可变快照引用。记录同时具有“经济报告期”“研究可用时间”“本系统获取时间”；这三个时钟不能相互代替。

新别名按来源分开，例如 `fd_income_revenue`、`fd_balance_total_assets`、`fd_cashflow_operating`。已有 `fd_ebit` 继续指向指标表，不静默改成利润表 EBIT。派生字段拥有独立公式版本、依赖字段版本与证据链；可使用 `model_fin_*`，但只有显式注册与真实计算完成后才进入目录。

| 第一批候选来源字段 | 语义与单位门槛 | 当前连接状态 |
| --- | --- | --- |
| income：revenue、total_revenue、operate_profit、n_income、n_income_attr_p、ebit、ebitda | 期间金额；累计/单季必须依据报表口径区别；币种及缩放逐字段核实 | 已在只读字段白名单，未自动加入时点因子 |
| income：basic_eps、diluted_eps | 每股金额；不能直接把累计 EPS 相加为 TTM 或与任意复权价格混算 | 同上 |
| balancesheet：total_assets、total_liab、total_hldr_eqy_exc_min_int、total_cur_assets、total_cur_liab | 报告期末存量；禁止把四季存量求和 | 同上 |
| balancesheet：money_cap、accounts_receiv、inventories、goodwill、st_borr、lt_borr | 存量与具体会计含义；借款之和不自动称“全部有息债务” | 同上 |
| cashflow：n_cashflow_act、n_cashflow_inv_act、n_cash_flows_fnc_act、c_pay_acq_const_fiolta、net_profit | 期间现金流或利润；现金支出字段符号需核验 | 同上 |
| cashflow：free_cashflow | 供应商定义需单独核实，不自动当作 FCFF、FCFE 或经营现金流减资本支出 | 同上 |

这张表来自当前仓库字段白名单，不是宣布官方全部字段已经取回。第二批才考虑研发/销售/管理费用、经营成本、合同资产与合同负债等额外字段；它们需要独立字段合同、有限样本证据和请求预算。

## 4. 公告可用日与修订冲突

建议新增版本化政策 `statement_asof_v1`：

1. 公告日及实际公告日都有效时，暂用两者较晚者作为保守候选日期，再取其后的首个官方交易日。只有一个有效日期则使用该日期并保留证据等级。**这是研究政策，不是对供应商历史日期真实性的证明。** 后续若获得原始公告时间戳，可增加更精确版本，不改旧快照。
2. 不能用报告期末、抓取日期或 `update_flag` 推定历史可用日。缺少可用日期、实际财务日期早于报告期、日历缺口均显式失败或隔离，不能补成可运行的历史。
3. 同证券、报告期、报表口径、有效公告日期的完全相同内容按哈希去重；字段冲突保留所有原始行并令该坐标不可用。不能按接口返回顺序、抓取顺序或 `update_flag=1` 猜哪项在当时可知。
4. 有明确较晚公告日期的修订只向未来生效；报告期选择与修订版本选择分开。更正上年度数据不替换最新季度的“最近报告期值”。
5. 抓到“最新修订后的历史序列”仍不足以证明 as-published 历史。标记 `PROVIDER_ORIGINAL_AS_PUBLISHED_VERSIONS_UNVERIFIED`，报告展示该边界；不能宣传已消除所有财务修订泄漏。
6. 每个查询时点保留计算所需的多个报告期版本，而非只保留最新一期。同比、季度差分、TTM 的每个依赖都要在该时点可用，派生字段可用日取依赖可用日的最大值。

年度累计流量转单季度，要求同财年、同合并范围、同币种与单位；四季度可由年报减前三季累计得到。TTM 可使用“四个匹配单季度之和”或“本年累计＋上一年全年－上年同期累计”，两种公式必须有版本与输入期核对。缺任何必要期间返回 null。不能对每日向前延续的财务字段调用交易日 rolling sum 来冒充 TTM。

## 5. 首批可计算配方：优先不同经济定义

下面是建议的 16 个研究状态，均为待实施候选。`TTM(x)` 指按上节真实期间规则构造；`avg_assets` 指同口径期初/期末资产均值；金额单位与适用行业必须先确认。所有输出进入预测函数 F 的输入状态，不直接宣称买卖方向或收益优势。

| 候选状态 | 明确公式 | 额外约束 |
| --- | --- | --- |
| 收入季度同比 | `revenue_q / revenue_q_prev_year - 1` | 上年收入须为正；两期同口径 |
| TTM 收入增长 | `TTM(revenue) / TTM(revenue)_prev_year - 1` | 需要完整可用期间；分母为正 |
| 经营利润率 | `TTM(operate_profit) / TTM(revenue)` | 收入为正；不跨行业混用金融收入定义 |
| 归母净利率 | `TTM(n_income_attr_p) / TTM(revenue)` | 明确分子是归母口径 |
| 经营现金收入比 | `TTM(n_cashflow_act) / TTM(revenue)` | 现金流与收入覆盖同期间 |
| 现金利润差 | `(TTM(n_income) - TTM(n_cashflow_act)) / avg_assets` | 合并净利润与合并现金流对齐；非归母利润替代 |
| 现金流资产比 | `TTM(n_cashflow_act) / avg_assets` | 平均资产为正 |
| 资本支出强度 | `TTM(c_pay_acq_const_fiolta) / TTM(revenue)` | 核验现金支出正负方向 |
| 经营现金流减购建支出 | `(TTM(n_cashflow_act) - TTM(c_pay_acq_const_fiolta)) / avg_assets` | 用完整公式命名，不等同企业自由现金流 |
| 资产增长 | `total_assets / total_assets_prev_year - 1` | 同期末、同口径，分母为正 |
| 现金资产占比 | `money_cap / total_assets` | 不将受限资金假定为可交易现金 |
| 流动性覆盖 | `total_cur_assets / total_cur_liab` | 流动负债为正；金融企业默认不适用 |
| 账面负债占比 | `total_liab / total_assets` | 账面负债，不等同有息债务 |
| 短长借款与资产比 | `(st_borr + lt_borr) / total_assets` | 明确只涵盖两项借款 |
| 应收账款资产占比 | `accounts_receiv / total_assets` | 不包装成回款天数；后者还需期间收入 |
| 商誉资产占比 | `goodwill / total_assets` | null 与零区分；金融企业按适用性登记 |

后续如加入市场估值比例，`daily_basic.total_mv` 的“万元”必须显式转换后才与金额比较；价格、股数、每股指标还需同一企业行动口径。金额百分比采用 ratio（0.1）还是 percent（10）应逐配方声明，不能混合排序输入尺度。[每日指标官方文档](https://tushare.pro/document/2?doc_id=32)

不以“所有字段 × 所有窗口”虚增因子数量。分别统计原始字段、配方定义、指定样本实际可计算配方、样本外检验结果。增加因子后沿用相同目标/日期/预算的去因子对照；负增量、不可用模型及未匹配样本照常保留。

## 6. 获取、缓存与覆盖

按“所选因子→实际依赖字段→所需报告期间→证券”规划请求，先查不可变缓存。接口各自定义日期范围语义、字段白名单、单次行数与权限；检测截断后拆区间，单日仍超限则失败，不使用残缺表。禁止自动升级 VIP、切换未授权供应商或按整个目录无界抓取。

在自动研究运行前生成覆盖摘要：证券数、报告期跨度、依赖非空率、公告可用日期缺失、冲突、单位未确认、行业不适用、历史修订未验证和可计算观察数。状态至少区分“只有定义”“适配器已实现但缺历史”“有样本且可计算”“冲突/单位/时点阻止计算”。不把 registry 的 `ready` 当作任意股票任意年份都有值。

新接口预算建议先离线 fixtures，后由独立的有限 canary 核对：一只一般工商业、一只金融企业、一次已知修订及跨年 TTM 所需期间。明确证券、端点、日期窗、最大请求数和缓存命中策略后再进行；**本轮没有执行这一步**。

## 7. 实施顺序与自动验收

| 阶段 | 交付 | 放行条件 |
| --- | --- | --- |
| A 字段合同 | 统一单位/期间/报表类型注册；旧别名不变 | 目录与引擎元数据同源；未确认单位不能通过相关公式 |
| B 时点版本 | 三表有限加载与不可变源快照；保留多个报告期 | 乱序、重复、修订、缺公告、交易日历边界全部有反例测试 |
| C 期间算子 | 季度与 TTM、依赖可用日、完整期间检查 | 缺一季不能算；未来修订扰动不改变过去输出 |
| D 配方与 UI | 上述配方逐个注册，显示来源/单位/口径/覆盖 | 每个配方至少一个手工可核对数值例和一个不可用例 |
| E 真实研究 | 有限真实源证据、冻结数据、F 预测与去因子对照 | 可重跑的 P/V/e/realized/error；缺失与负增量保留；不宣称盈利 |

必须保留并扩展的测试清单：

- 周末公告、两公告日期不一致、公告当日不能使用、可用日期晚于观察日拒绝。
- 同日冲突字段隔离为 null；行顺序置换结果一致；修订前已保存快照及预测哈希不变。
- 旧报告期修订不覆盖最新报告期；新季度 null 不从旧季度补值。
- 合并与母公司、累计与单季不能混算；银行的工业企业现金转换公式显式不适用。
- 缺一个 TTM 依赖期、报告期间不连续、现金支出符号未确认，均不能生成假值。
- 金额/万元、股/万股、ratio/percent 的 10,000 与 100 倍错配要被测试捕获。
- 零/负分母各配方有明确政策；不无限值、不悄悄取绝对值、不填零。
- 截断、重复页、日期筛选语义不同、字段整段消失均有失败/覆盖状态。
- 新财务状态经 F 模型形成显式预测；重做执行只复用预测产物，不能改写源数据或重新训练。
