# Isolated financial acquisition consumer

Status: implemented Python candidate for `financial-acquire/v1`. It is a separate,
explicitly enabled process. This document does not assert a production deployment
or a successful real provider call. The existing `financial-input/v1` consumer
continues to validate, revise and prepare frozen inputs without provider access.

## Fixed profile and identities

`engine/atlas_quant/financial_acquisition/profile.json` is shared with the edge
planner. `annual_statements_2_v1` permits one or two securities on one SH or SZ
venue, one December annual period, and a calendar interval of at most 366 days.
It first requests the exact venue calendar, then income, balance sheet and cash
flow for each sorted security. The maximum is six statements plus one calendar.
The general-company, consolidated, YTD scope is explicit. Mixed venues, pagination,
field repair, alternative endpoints and inferred calendars are refused.

Every request identity hashes the endpoint, parameters, ordered fields, profile,
normalizer and nonsecret authorization scope. Python verifies the displayed
reviewed plan root, rebuilds the fixed profile independently, then verifies the
execution root. Start-time cache upgrades may replace a miss with a frozen hit;
a reviewed hit cannot change. A checked-in fixture generated by the actual JS
planner verifies the cross-language plan identity.

Cache receipts are authorized by the configured entitlement scope, not just
symbol or endpoint. Production rejects fixture receipts even when the hash and
request key match. This does not claim that a configured scope independently
proves a vendor license; the operator must assign it to the authorized entitlement.

## Process and recovery boundary

The production CLI is:

```sh
python -m atlas_quant.financial_acquisition --config /absolute/private/config.json
```

The existing secure config loader requires a private absolute 0600 file. In
addition to `api_base`, `runner_secret`, `delivery_dir` and the existing approved
private `provider_access` (or explicit `tushare_token`), the process requires:

- `acquisition_enabled: true` and the fixed `authorization_scope`.
- Optional `acquisition_delivery_dir`, an absolute 0700 directory independent of
  both research and financial preparation delivery directories.
- Production CLI always rejects `allow_acquisition_fixtures: true`. Tests inject
  that switch and an explicit fixture provider through the library only.

The real adapter configuration is checked locally before any spool or claim:
missing credentials, an invalid scope or an unapproved proxy URL cannot consume
an irreversible provider intent. This check opens no HTTP connection and does
not establish that the token has vendor permission. Explicit injected fixture
providers retain their separate test-only construction path.

No acquisition launcher is installed or started by importing the module. Tokens
stay in private process configuration; they are excluded from plans, cache keys,
publications, logs and research artifacts. The provider adapter has a fixed HTTPS
URL, no redirects, no automatic retry and no fallback. It does not call the
existing retrying `TushareClient.call` implementation.

Recovery order:

1. Persist the claim UUID before `/claim`. Every recovery uses that same UUID.
2. Persist a request attempt UUID before `/begin`. Only the first acknowledged
   `maySend: true` permits the child process to send the fixed request.
3. Persist the `calling` state before starting the child. The child encrypts and
   fsyncs the exact complete HTTP entity response plus status/time/source metadata
   before parsing it, publishing it, or permitting the next request.
4. Upload the exact durable response as its receipt. Lost upload ACKs replay only
   these saved bytes. They never invoke the provider again.
5. Validate calendar completeness first and each statement immediately after its
   durable receipt. Definite HTTP/API errors retain the response and stop later
   requests. Empty and full-limit statement responses are refused.
6. Freeze the package without unit bindings under `verified_only`. Save every
   encrypted publication part before its manifest commit marker. Deliver missing
   parts, complete, then read the same claim's terminal receipt before cleanup.

A replayed begin without a local raw response, a child crash/timeout, an incomplete
response or an interrupted `calling` state becomes `PROVIDER_OUTCOME_UNKNOWN`.
There is no automatic resend, even when the process may have stopped before its
first network byte. The edge intent is sticky across new plans. Failed/cancelled
local evidence is retained as encrypted `*-review.enc` plus any response files;
manual review decides its disposition. A terminal claim readback lets the process
move to unrelated jobs without erasing that evidence. Rotating the runner secret,
API base or authorization scope while this evidence is outstanding requires an
explicit migration: old ciphertext must not be silently discarded.

Control-plane requests may be retried from durable state. They use the same
claim, attempt, raw receipt, publication hash and bytes. Lease identity mismatch
or unavailable control readback retains the state. The service does not guess
success. An idle heartbeat with `canClaim:false` creates no new claim; an existing durable
claim still resumes regardless of that queue gate. A fixed 600-second job deadline
and 120-second renewable lease come from the edge. The monitor checks every 20
seconds; transient network/5xx responses allow a bounded retry within the last
explicitly confirmed lease only. Unknown heartbeats cannot extend that lease or
the fixed deadline. Cancellation, invalid leases, authorization and protocol
failures stop immediately. SIGTERM/SIGINT stop new claims and interrupt an active
child through the same durable unknown-result boundary. Each provider child has a hard
30-second wall-clock budget and is terminated on cancellation or deadline.

## Resource and evidence limits

Each raw response is at most 4 MiB; all raw responses together are at most 16 MiB.
The next child receives only the remaining parent byte budget. Complete raw bytes
above the remaining budget are not fabricated or truncated into a receipt: the
attempt becomes unknown/manual review. Requests with no remaining budget do not
start. Normalized statements are restricted to the fixed columns and fewer than
1,000 records per response. The frozen package is at most 24 MiB, the calendar
registry envelope at most 256 KiB, each part at most 512 KiB, and the publication
manifest at most 128 KiB. The exact server limit profile is checked before work.

The normalized package preserves the existing core representation:
`wireBytesAvailable:false`, `wireNumericLexemesAvailable:false`. It does not
pretend a reconstructed numeric table is the raw response. Exact delivered endpoint response
bytes remain private receipts; the publication and input acquisition metadata
bind each normalized snapshot to the exact request/receipt hash. HTTP entity bytes here mean the bytes delivered by the configured endpoint, excluding
transport framing and HTTP headers. In private-proxy mode the Worker already
parses and reserializes upstream JSON: these are the proxy response bytes, **not**
the original Tushare wire bytes. No upstream wire identity is claimed. Compression is refused
so transparent decompression cannot change the claimed raw identity.

The calendar registry is private to the resulting input owner. Its evidence
reference includes the exact raw calendar receipt SHA. `official` here means
provider-reported official calendar, not independent source authentication.
Fixtures use `kind:fixture`, a `SYNTHETIC_FIXTURE:` reference and an explicit
synthetic evidence level; fixture receipts require a separately enabled test edge.

Completion creates an **uploaded** financial input. It does not prepare states,
verify units, certify original-as-published history, admit a research dataset or
permit a model/execution. Validation and preparation remain separate operations.
All unit bindings are initially empty, so missing results are an expected honest
outcome until an authorized proof or explicit unit declaration is supplied.

## Acceptance evidence

`engine/tests/test_financial_acquisition.py` covers real spawned child processes,
control ACK loss, crash recovery, cancellation, deadline termination, cache and
authorization isolation, raw tampering, fixed request validation, JS planner
identity, core package decoding/preparation and synthetic source labeling.

The isolated localhost acceptance used the actual Python consumer and actual
HTTP/D1/R2 endpoints with an injected synthetic provider. Four fixture requests
produced a 3,911-byte package; owner source download SHA and roots matched, and
core preparation recomputed three missing rows under `verified_only`. A complete
response rejected an initial fixture-reference mismatch; after its edge fix, the
same claim/manifest resumed with four total fixture calls and no provider calls.
This is transport/core evidence, not a real Tushare entitlement or data-quality
acceptance. Private receipts and session configuration are excluded from Git.
