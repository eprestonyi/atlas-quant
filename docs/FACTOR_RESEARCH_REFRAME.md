# 因子研究工作区重构

2026-10-08 用户修正后的产品合同，优先于旧八步交易流程。整项工程仍未完成；本轮先完成因子研究，策略、执行和检测使用不同的工作区与产物。

## 入口与职责

轻松模式 / Studio → 统计量化交易 → 因子研究 / 策略研究 / 执行仪器 / 检测仪。

因子研究只产生可检查的条件模型 F、预测和诊断。策略研究以后导入冻结模型，单独声明收益目标、方向、对冲、风险和成本，再做策略回测。执行仪器消费已经版本化的策略和阈值；没有交易所数据及执行连接时不伪造高频或实时成交。检测仪未来使用独立监控自选（可导入 Atlas 自选）与选定模型，观察 e；监控集合不必等于训练集合，但必须通过模型输入和适用范围检查。

## 因子研究六步

1. 股票筛选：只有集合及 filter 的并、交、剔除和完整结果。删除第二次手选研究子集、抽样按钮及 1/50 提示；不自动截断。完整集合在服务端冻结并绑定每个研究版本。容量不足整单拒绝，并报告资源原因。
2. 研究机制：状态均值回归、配对相对价值、趋势条件预测、基本面条件预测、事件条件预测五选一。机制决定目标和特征条件；自动选型只在该机制内比较估计方法，不能更换用户的研究假设。
3. 研究设置：数据、研究日期、观察粒度、预测期限及目标。日期不再位于股票筛选页。默认使用数据源已支持的最小粒度；当前日频数据不能称为分钟或实时数据。
4. 因子输入：选择和组合有公式、单位、来源与可用时点的状态。显示真实缺失和可用性，字段目录数量不是已验证的因子数量。
5. 拟合与检验：轻松模式由系统执行预声明的候选和验证协议；Studio 提供细节。因子研究关闭交易执行，不要求设置仓位、磨损或交易阈值。
6. F 模型与报告：完整输入模式、训练变换、拟合参数或树、训练截止、目标、适用范围、模型选择审计、预测和因子统计。导出可计算的纯 JSON 函数；受限编辑生成新的派生产物，不篡改原始结果，也不继承原模型的检验结论。

## 数学与证据边界

用户主输出仍为 V̂(t,h)=F_h(X_t)，e=P_t−V̂，ΔP̂=−e。现有双输出预测内部保留入场/未来目标兼容，函数明确将标准化条件变化还原为 V=P+scale×g(X)；当前状态和尺度属于显式输入，不藏在全局状态里。

当前 `atlas-model-function/1` 的 h 从下一官方交易日开盘起算：观察收盘后估计下一开盘及其后 h 个交易日开盘。默认观察间隔 1 不等于预测期限 h=1；完整输出解释见 [独立 F 函数时间口径](MODEL_FUNCTION.md)。旧预测、函数及其 hash 保留原语义。

Grid search、随机搜索和梯度下降都不能保证没有过拟合。候选、预算及时间切分事先确定；训练折拟合预处理和参数，内层选择估计器/正则，外层评价选择过程，终端报告不参与选型。预声明滚动拟合可以使用此前已经成熟的终端标签，因此结果标为顺序样本外，而非完全不再训练的锁箱。重复看结果后手调模型仍可能发生研究者选择偏差，系统保留版本及编辑来源。

方法依据：[scikit-learn 嵌套验证说明](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html)、[按时间切分及 gap](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)。RL 属于需要另行定义状态、动作、奖励与环境的序贯决策问题，本轮不把它自动混入监督条件函数的候选。

统计表必须说明样本、时间区间、单位和缺失处理。横截面 IC/Rank IC 按日期计算；单资产不能伪造横截面 IC，可单列时序相关。相关、协方差和二维经验联合频数/概率表不表示因果关系。正则系数不套用未经验证的 OLS t 检验；未处理依赖时不显示伪精确显著性。描述拟合度和样本外预测表现分别标注。

## 验收顺序

先完成 UI/保存合同、完整集合预检、可执行函数和分片诊断；再做跨 Python/JavaScript 数值复现、受限编辑和来源隔离反例。实际浏览器必须走完选择→保存→刷新→拟合→报告→下载→派生函数计算。完整池容量用预声明合成案例测量，逐估计器报告预算；不能把多个 50 股独立模型拼成一个全池模型。最后才进入独立生产迁移与真实冻结源验收。

## 下一轮时间目标版本化建议

若纯因子研究改成从观察日直接起算 h，应在新预测/函数 schema 中明确版本化 `targetTiming`：信息截止为观察收盘后、目标偏移从观察日计算、目标价格使用开盘还是收盘；入场时点归独立策略模块。界面给出完整目标日期说明，不让用户猜底层字段。旧 schema 1 缺少该结构时始终按 `legacy_next_open_plus_h` 解释，禁止更改旧 h、标签或文件 hash。新定义必须进入预测配置与函数身份，重新验证日历、标签成熟与清除规则、跨运行时求值和容量；不同时间口径不能冒称同一受控比较。本段仅为下一轮设计，尚未实现。
