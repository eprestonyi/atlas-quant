# Factor transformation and independent reconciliation

2026-10-11. This is the audit contract for `auto-factor-preprocess/2`. It does not retroactively change the meanings, numbers, or hashes of archived version-1 functions. Implementation and production acceptance are separate evidence gates.

## Three distinct mathematical stages

`raw observation → economic quantity R → frozen training transform X → fitted F(X)`.

An economic transform determines what the input means. Clipping, imputation, and scaling condition the numerical fitting problem; they cannot fix an incorrect currency, corporate-action adjustment, time join, or economic definition. Neither stage proves normality, stationarity, predictability, or an economically tradable residual. The portable function accepts its declared constructed inputs; it must not apply the raw-data transform a second time.

For a single positive-price asset, the current output remains `(future state − current price)/current price`; the target is the opening price at origin + 1 + h sessions. This is distinct from the current-session close-to-close return, a log return, and an ex-post forecast error. Signed basket states require their declared positive gross scale, not division by a possibly zero net spread.

## Economic meaning and units

These are defensible quantities, not a claim that one transform is universally optimal. References motivate the quantity or establish a source unit. They do **not** mandate Atlas's 20-session window, sample standard deviation, 1%/99% clipping, median imputation, IQR scaling, or a particular predictive model.

Lagging a volatility estimate is a causality decision; if an input is observed after today's close, today's realized return may be known, but including it in its own denominator changes the shock measure. Our previous-return denominator is an explicit definition, not the only mathematically legal choice. [Moreira–Muir](https://www.nber.org/papers/w22208) studies managed **portfolio exposure**; it must not be cited as a proof that Atlas's every price input should use precisely the same normalization.

## Small, explicit compound-expression contract

Version 1 automatically recognizes only a bare AST field. `+close`, `close*1`, `lag(close,1)`, `ts_mean(close,20)` and `raw_close+0` bypass that recognition. Thus syntactic validity is not evidence that an expression has an appropriate economic output.

For a new protocol, validate the whole tree before fitting:

1. Register raw quantity, source/native unit, adjustment, scope and availability. Reject raw unadjusted prices as return inputs, including nested expressions. The narrow exception is a declared currency-per-share financial numerator divided directly by raw close, such as `fd_eps/raw_close`: that is a valuation yield, not a corporate-action return. Do not infer semantics from display labels.
2. Record whether each operator preserves a quantity or explicitly constructs another. Lag/mean/min/max/clip/absolute value preserve units; differences and standard deviation do not make a price dimensionless. A validated price return, same-source relative deviation or deliberate log-positive size feature is a constructed input and must not be transformed again.
3. Addition/subtraction require compatible quantities. A cross-source price ratio may be algebraically dimensionless yet depend on arbitrary index rebasing; acceptance as a ratio does not establish a tradable relative value. Incompatible currencies/units must fail. Unknown output semantics require an explicit transform choice before fitting. Explicit custom declarations cannot waive known unit incompatibility or the raw-price guard.
4. Pure global `rank`/`zscore` cannot use a single-series same-date population. Named-industry global input, membership-conditioned industry input, own-stock input and reference-stock input remain different scopes.
5. Freeze output quantity, inferred/explicit origin, complete source units, transform parameters, direction, scope and aggregation in the function identity. Keep version 1 readable and bitwise unchanged. Do not silently upgrade imported functions.

This is a constrained semantic checker, not symbolic proof of stationarity. Acceptance of an expression says its declared units and operations agree, not that its hypothesis works.

The version-2 defaults are simple one-session returns for positive price levels, first differences for log-price levels, log-positive capitalization/share count, reciprocal multiples, percent/100, and signed `log1p(abs(value)/1 native unit)` for signed financial monetary/per-share levels and changes. Explicitly constructed ratios retain identity. `log(close)` therefore produces a log return after its first difference; `log(close)-log(lag(close,1))` is already a log return and retains identity. Price differences and price standard deviations need a declared denominator or explicit custom treatment; wrappers do not turn them into returns.

Activity `log1p` and signed financial `log1p` currently retain a **frozen native reference unit**, not a universal canonical-currency conversion. This is reproducible but not invariant to relabeling hands as shares, CNY thousands as CNY, or CNY as USD. No such conversion is silently inferred. Their source unit must accompany the function; comparing a feature across providers requires an explicit unit reconciliation. Multiplicative price rebasing, in contrast, cancels in the simple/log return definitions and is covered by independent tests.

## Numerical fitting and independent acceptance

Fit clipping bounds, fill values, center and scale on each actual, maturity-purged training fold. Global features contribute one value per source-aligned research date; pooled asset inputs retain their declared row population. Preserve observed/missing counts and degenerate-scale handling. IQR scaling does not force variance one, remove dependence, or make a distribution Gaussian. See [scikit-learn's leakage guidance](https://scikit-learn.org/stable/common_pitfalls.html).

Independent acceptance must start from archived observations, without importing the engine's transform helpers:

- Verify provider identity, declared unit, unique dates, source/root hashes, adjustment reconstruction, availability and exact sample membership before any regression.
- Recompute simple/log returns, lagged-volatility shocks, log size, inverse valuations, percentage conversion, activity-unit conversion and valid identity features; compare every value and missing mask with system constructed inputs.
- Recompute train-only clipping/imputation/median/IQR with a separately written oracle; compare frozen vectors, population counts and final model inputs. Add unit-rescaling, future-perturbation, constant-series, missing-date and compound-bypass counterexamples.
- Keep contemporaneous OLS and forward-label OLS separate. State per-asset, pooled, pooled-with-asset-intercepts or basket regression explicitly. A time-varying volatility divisor changes the regressor and generally changes R²; a fixed nonzero affine regressor transformation with an intercept does not.
- Show normalized factor equations and raw→R→X definitions together. Report pairwise finite counts and the actual target/window. Do not impose a desired R² by selecting windows or transforms after seeing results.
- Distinguish source numeric consistency, third-party spot reconciliation, full provider-history verification, model tests and production readback. A content hash proves byte identity, not historical truth. Missing original financial disclosures prevent independent PIT-join reconstruction even if all projected availability dates pass.

Six requested factor columns plus four derived state columns reproduce the archived distributions and forward univariate R² to floating-point tolerance. This is numerical consistency, not independent certification of every provider observation.
