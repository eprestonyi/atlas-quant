# 整池预测与因子研究扩容设计

状态：**下一轮设计，尚未实现、尚未验收**。本文不改变 v0.4 发布候选的容量、统计方法或数据授权。本次仅分析现有代码并提出分阶段改造；沪深 300／中证 1000 整池运行不属于当前已交付能力。

目标是让一次研究在完整、明确的证券池中，完成 `V = F_h(X)` 的预测、因子增量检验和可追溯执行实验。因子配方数量、字段定义数量、股票数量、模型候选数量和独立策略实验数量是五个不同指标；大量目录条目不能证明大量策略已经实现或验证。

## 1. 当前边界与直接放大时的瓶颈

| 维度 | v0.4 发布候选 | 扩容影响 |
| --- | --- | --- |
| 研究证券池 | 1–50 只；最长 8 年 | 整池输入、特征、样本、风险计算均增长 |
| 单个冻结篮子 | 1–20 腿；pair 固定 2 腿 | 不能把 1000 只股票的池解释成一个已支持的 1000 腿篮子 |
| 每个研究配置 | 最多 32 个因子；auto 是 8 个有限参数配置 | 目录不等于同时运行的因子／模型／策略数量 |
| 数据与样本 | 输入最多 110,000 行；预测样本最多 110,000 个 | 增大池后通常先触达这些限制 |
| 终段完整预测 | 最多 25,000 条，包括无效与未成熟记录 | 同期 state-only 因子基线另保留完整记录 |
| 存储／传输 | 结果、预测产物、冻结快照各最多 24 MiB；单请求 envelope 26 MiB | 多处独立上限，不是只修改一个常量即可 |
| 执行资源 | 每任务最多 900 秒；当前主机单计算槽 | 长研究不能靠不断续租绕过预算 |
| Provider | 当前每任务最多 512 次真实 HTTP 尝试；重试也计数 | 冷数据按证券逐只读取，整池需改变采集协议 |

代码依据：[schema.py](../engine/atlas_quant/statistical_quant/schema.py)、[targets.py](../engine/atlas_quant/statistical_quant/targets.py)、[validation.py](../engine/atlas_quant/statistical_quant/validation.py)、[provider.py](../engine/atlas_quant/provider.py)、[runner.py](../engine/atlas_quant/runner.py)、[runner_artifacts.py](../engine/atlas_quant/runner_artifacts.py)、[persistence.mjs](../edge/statistical-quant/persistence.mjs)。

当前冷取最少是一次交易日历，加每证券 `daily` 与 `adj_factor`：300 只至少 601 次，1000 只至少 2001 次；需要 `daily_basic` 时分别至少 901／3001 次。财务数据和网络重试还会增加调用。以上是当前调用循环的计算，不是供应商授权或吞吐承诺。不得通过轮换凭据规避限制，也不能让每个模型候选再次取同一份行情。

用于判断量级的示例：假设五年有 1250 个研究交易日、终段约 250 日、每日观察、每证券一个目标，不计预热，则 300／1000 只约产生 37.5 万／125 万输入格点和 7.5 万／25 万终段预测；附加因子基线后终段预测记录约翻倍。仅 32 个 float64 特征的稠密数组约需 96／320 MB，尚不包括原始行情、缺失掩码、标签、pandas 索引、模型、预处理副本和序列化对象。这是算术估计，不是实际官方日历、RSS 或运行时间测量。

历史开发证据中，20 股／5 年／8 因子／auto 的合成运行产生 4980 条主预测和同量基线，去掉报告外层重复明细后 compact 报告约 8.53 MB；50 股／8 年／32 因子／auto 的一次旧候选合成测试约 220 秒后明确 `RESULT_SIZE`，没有返回截断产物。这些记录早于最终 compact 预算修订，不代表最终候选或整池验收，也不能线性外推耗时。

## 2. 必须保留的统计与交易语义

### 全池模型不能变成若干子池模型

当前 `asset_price` 的目标逐证券建立，但训练器把同一训练窗口内的证券样本合并拟合一个双输出模型。它不是为每只股票独立选模型。特征 DSL 的 `rank`／`zscore` 使用同一日期、整个研究池；预处理的截尾、填补、标准化与去相关只在对应训练样本拟合；选择和终段指标按日期等权。

因此，不能把 1000 股切成 20 个 50 股旧任务、分别计算 rank、分别选冠军、最后把曲线拼起来，并称为同一个整池研究。这样会同时改变特征、训练分布、选择问题、日期权重和风险约束。若以后允许行业／分组模型，应作为显式新模型定义，版本化分组规则，并另做验证。

当前拟合损失本身仍由估计器在训练行上计算；日期等权主要用于模型选择与报告评分。扩容时不能偷偷把训练也改为日期等权。若新增 sample-weight 能力，需要单独的配置、模型支持检查和统计版本。

### 切分的是计算与存储，不是信息集

允许按证券切分原始读取和独立时间序列特征；时间切块必须带足 DSL 嵌套 lookback、训练窗口和标签端点所需的上下文。只带一个固定 60 日 halo 不能覆盖所有表达式。

跨证券 rank、zscore、PCA、截面暴露和整体风险必须经过同日期的全池汇合。嵌套表达式如 `ts_mean(rank(returns(close,5)),20)` 需要先汇合每日 rank，再计算其时间窗口；应从 DSL AST 建立依赖图，不能只按最外层函数粗略分类。

训练任务可按候选、验证折和主模型／state-only 基线并行，但每个任务必须读取相同的全局日期划分与其对应完整训练矩阵。相同模型的推断可以按证券批量执行，前提是预处理与模型已经冻结。禁止把各分片的模型平均冒充原来全池训练的估计器。

若进一步做精确分布式线性求解，需先完成全局训练预处理，再验证充分统计量归约与参考解一致；各片 median 的平均数不是全局 median，各片相关矩阵的简单平均也不是原样本的相关矩阵。ElasticNet 与 HGB 不能通过平均子模型保持原估计器含义；首轮没有必要为所有模型实现分布式训练。

### 冻结篮子、验证和执行不能因扩容降格

- 每个 origin 的 q 只由其截止前数据构造；训练与验证样本使用各自历史时点形成的 q。不能用外层或终段形成的 PCA／配对系数回填内层样本。
- 所有内外折仍按全局唯一日期切分，双标签均严格成熟后才能进入训练。终段只允许预先声明的滚动再拟合，不再选择冠军。
- entry 与 exit 两个目标仍对应下一开盘与之后的目标开盘，不能为便于切块把收盘至次日开盘收益算成可实现收益。
- 主模型与因子基线保持相同目标、输入缺失／事件 mask、日期划分和候选预算；有效输出 mask 可以不同，必须保留覆盖差异。不能只汇总完成较快或表现较好的分片。
- 执行按日期统一消费已冻结 forecastId。净持仓、现金、费用、借券假设、T+1、锁盘、原子篮子及风险约束不能在多个独立现金账户中回测后相加。
- 不改变历史成员资格边界。仅能获取当前成分时，产物明确记录“当前池回看”；具有可核验的成分生效历史后，才能新增 PIT membership 研究模式。

## 3. 计算复杂度与安全切分点

记证券数 N、交易日数 T、特征数 F、预测目标数 J、候选数 C、内外折数 I／O、终段再拟合次数 R。当前 J 在单资产模式约为 N；固定／配对篮子为 1；PCA 残差构造通常产生多个目标，且每个目标可含整个篮子。

| 阶段 | 主要成本 | 可靠切分方式 |
| --- | --- | --- |
| 数据冻结与 PIT joins | 大致随输入行及披露行增长；网络预算常先成为瓶颈 | 证券／日期分区读取，共享官方日历、全局版本与缺失规则；采集完成后生成不可变快照 |
| 时间序列因子 | 多数随 N×T×F 增长；rolling rank 等函数另有窗口成本 | 依赖感知的证券／时间块；保留缺失与上下文，消除重复 halo 输出 |
| 横截面因子 | rank 约按每日期 N log N；zscore 需要全池统计 | 全日期 reducer；再分发结果，不在局部池重定义排名 |
| 样本与标签 | J×观察日数，当前有大量逐 origin pandas 取行与字典对象 | 数组化、稳定 originIndex、列式存储；不能先只生成可交易或有效记录 |
| 模型训练 | Ridge 常见稠密实现约 mF²；ElasticNet 随迭代数×mF；HGB 与分箱／树／双输出有关 | 全局训练矩阵的独立 candidate/fold 任务；先优化单机数组与有限候选并行 |
| 验证／终段 | 约 B×[C×I×(O+1)+O+R] 次拟合，B=1 或含基线时 2 | 依赖 DAG；固定 cutoff 与成熟 mask，汇总完全部内折再决定冠军 |
| 指标／因子增量 | 输入记录数；日期聚合可流式 | 每日所有目标先合并 loss sum/count，再等权平均日期；不可平均分片的平均数 |
| 执行风险 | 稠密协方差约 N²×lookback；PSD 分解一般 N³ | 先保留池与活跃腿集合的明确边界；更换低秩风险模型须版本化并独立验收 |

模型训练复杂度仅说明主要增长项，不是实际 sklearn 运行时间或内存保证。当前双输出 HGB 实际分别拟合两个估计器，不能按一个单输出模型估预算。候选共享中间结果的缓存键必须含实际成熟训练 mask；仅按相同日期范围缓存会误复用不同有效样本的预处理。

### 大池不等于一个巨大 PCA 篮子

现实现每次 PCA 形成会生成多个 N 腿 q，并在目标定义中重复 loadings 等审计资料；若直接扩到 N=1000，会形成平方级 q 存储，重复 loadings 还可能更大。逐 origin 对每个目标重新构造 61 日状态也会放大计算。

最小路径是先支持 300／1000 股全池单资产预测及因子研究，保持 20 腿篮子上限。第二阶段可增加显式 `targetGroups`，每个组采用预声明的小篮子，但因子横截面仍按指定全池计算，并明确是分组目标。不得自动搜索全池所有配对：N=1000 已有 499,500 个无序对，需要另行声明形成期筛选、候选图、试验预算及选择偏差。

若确需全池共同成分，则把 `hedgeFit`、loadings、q 矩阵与各目标的列引用分开存储；同一形成时点只存一份矩阵。采用有限 rank 的分解和矩阵批量运算，并验证其与小池参考实现的 q、预测及台账一致。近似 PCA、稀疏对冲或低秩风险都是统计方法变更，不是透明的压缩优化。

## 4. 分阶段落地

### 阶段 A：完整分片产物与冻结数据，先不提高证券上限

先解除“必须一次返回全部 JSON”这一结构性约束。新增预测 artifact schema v2，与现有 strategy schemaVersion=2 分开版本管理；旧 artifact v1 保持原身份校验与重放，不把旧 artifactId 重新解释成新 manifest hash。

建议分离对象：

1. `datasetManifest`：数据字段 schema、单位／调整方式、日历、证券顺序、成员版本、来源／权限说明与按稳定区间分片的原始数据。
2. `featureManifest`：表达式 AST／版本、依赖图、来源快照、PIT 可用性掩码及特征分片；没有真实数据的定义仍只是目录。
3. `forecastManifest`：sourceStrategy、predictionConfigHash、engine／依赖版本、数据／特征根 hash、计划 origin index、主预测、基线、目标、拟合审计、诊断分片。
4. `executionManifest`：原 forecast 根身份、独立执行配置、全日账本、持仓、决策和成交分片。引用预测，绝不通过重放重新获取行情或拟合。

分片大小初始建议：目标 4 MiB、解压后不超过 8 MiB；这是待基准验证的协议预算，不是已实现限额。数据可用 Parquet／Arrow，接口元数据与小预览用 JSON。需要同时设压缩字节、解压字节、行数、分片数、字段数和整个实验上限，不能只限制压缩包以致解压耗尽内存。

每个分片 descriptor 含 `kind/schemaVersion/ordinal/range/rowCount/byteLength/decodedByteLength/contentSha256`，根 manifest 含完整有序 descriptor 集合和各类别总数。内容 hash 覆盖确切存储字节；根身份覆盖规范化逻辑 manifest，排除临时 URL、存储路径和上传时间等非语义字段，并明确跨语言数字与空值编码规则。若更换列式 writer 使字节不同，必须如实产生不同物理对象 hash；不能仅凭逻辑近似相等声称同一不可变对象。

hash 只能证明已提交字节未变，不能证明没有漏预测。finalize 还须核对预先冻结的 expectedOriginCount、originIndexRoot、日期范围、每日期目标集合、唯一性、主／基线匹配规则、目标／拟合引用完整性和 invalid／tail 记录。完整性核验成功后原子发布 `complete`；丢任一分片、重复一段或跨 owner 引用均不得产生可执行 artifact。

建议端点族为 `begin / upload-chunk / finalize / manifest / page / download`，每步有内容身份和幂等键。具体 URL 要在下一轮合同定稿，不能让现在 UI 调用未实现接口。上传到私有 R2 staging，D1 管理 owner、计划、状态与 commit 指针；仅 finalize 完整 manifest 后允许创建 execution。staging 清理由未被完整产物引用且已确定失败／取消的对象开始，不能删除仍有有效租约的分片。

当前 forecast preview 是响应分页：`forecastResponse` 先读取并校验整个 R2 对象，之后才 slice；正式报告也通过 `/runs/:id` 整包读取，浏览器再 copy／filter／sort。扩容需要 summary 首屏、绑定不可变 manifestHash 的 cursor，以及预测／模型／目标／风险／台账各自的详情接口；客户端只缓存有限页。导出由服务端流式返回 manifest 和原始分片，不能先在浏览器 JSON.stringify 全报告再生成 Blob。实验列表现有固定 100 条上限也需明确 hasMore／cursor，避免将最近记录误称全部历史。

### 阶段 B：300 股全池单机预测与因子研究

先建可测资源准入器，预估／探测行数、特征字节、目标数、双基线输出、拟合次数、provider 调用与结果大小。提交前返回 plan 与预算；无法估计的字段明确标为 unknown，运行中继续硬限制。超预算明确拒绝，不能静默缩池、抽样、删因子或关闭基线。

改造为列式／memory-mapped 数据与特征、向量化样本构造、全局 fold plan、流式预测 writer。训练器先仍使用相同的全池 sklearn 算法；超过单机 RAM 的训练配置明确不支持，不能把不支持 partial_fit 的模型伪装成在线训练。

对于 Provider，先实现基于授权入口的可恢复数据集采集任务，调用与重试预算独立计数，全局限流，多模型复用同一冻结输入。是否采用按日期批量接口、何种页数／历史深度，都须由真实账号权限和接口能力验证决定。供应商当前修订数据不能冒称历史原始版本档案。数据集采集进度可以保存，但未完整冻结的数据集不能自动作为全池研究输入。

先验收 forecast-only，再验收单一全池组合的顺序执行。CPU 并行度从可测的小值开始，避免 sklearn／BLAS 线程与多个候选进程叠加超额占用。股票上限、最大因子数、候选预算、输出上限应由能力 profile 联动，而非各自独立提高。

### 阶段 C：1000 股与可恢复研究 DAG

在 300 股结果和资源证据通过后，增加父研究与阶段任务：冻结数据 → 特征依赖 DAG → 全局 samples／fold plan → 各候选内折 → 冠军汇总 → 外折／终段再拟合及预测 → 因子基线配对 → 完整产物提交。先保留少量主机／进程，证据证明需要时再引入分布式调度，不预先增加集群复杂度。

每个逻辑阶段有稳定 `stageId = hash(plan + inputs + version)`；每次运行另有 attempt／lease／fencing token。租约恢复不能产生第二个逻辑任务，迟到旧 attempt 不能覆盖新结果。采用至少一次交付、内容幂等提交，而不是承诺不可证的“网络恰好一次”。当前 durable claim UUID 协议是基础，但不能替代阶段 DAG 的依赖状态和 fencing。

中断后优先复用已完整确认的数据／特征／拟合输出；是否重试失败的纯计算阶段必须由预先声明次数和总预算控制。Provider 阶段只续读已核对的缺片，不在未知请求结果时盲目重做全部采集。取消父任务要传播到子任务，停止新 claim／拟合，并限制退出延迟；保留已完成分片供审计但标记研究 incomplete，不以部分成功结果宣布完成。

拟合审计不是可恢复的完整模型文件；当前 HGB 审计尤其不能直接恢复估计器。若要从“拟合完、预测未完”恢复，需要安全、版本化且可验证的模型状态格式，或明确仅允许按原预算重做纯计算拟合。不得从上传内容加载任意 pickle。执行日期块只能串行消费，checkpoint 须包含现金、净持仓、逐 ticket 冻结腿与成本、T+1 可卖年龄、未完成原子退出／风险状态及已消费 forecastId；只有完整校验该状态后才可显示“暂停／恢复”，不能给现有取消按钮换名。

实验预算至少分别包含：provider 真实尝试数、累计 CPU 时间、总 wall-clock 截止、每任务 wall-clock、峰值 RSS、临时盘、结果字节、并发槽数、候选／折次数。每个阶段仍可设 900 秒等有限硬边界；父实验总预算需要另行定值。把一次研究拆成无限个 900 秒子任务等于绕过限额，应由父预算阻止。

### 阶段 D：更多模型与因子实验，不与容量混为一谈

在完整审计、预算与重放成立后，再加入版本化 model/factor/target/risk adapter 注册与独立能力声明。增加 100 个表达式不等于 100 个研究策略；独立策略包含目标、信息集、拟合／选择、执行和风险规则的完整配置。批量组合试验必须保留失败与未通过结果、试验家族及选择历史；多重研究推断方法单独设计，不因扩容就宣称 alpha 或获利。

## 5. 必须同步修改的协议边界

| 层 | 下一轮需要的改变 |
| --- | --- |
| 配置／能力 | 不直接放松所有旧 schema；增加明确能力 profile、预算、成员版本和目标上限，JS／Python共享接受与拒绝 fixtures |
| Provider／上传 | 以冻结 dataset manifest 引用代替整包上传；接口能力与授权单独验证；保持字段单位、可用日、版本与缺失审计 |
| 数值引擎 | `Samples`／forecast 全内存 list 改为分区读写接口；全局日期／目标／模型语义固定；完整记录 writer 不允许截断 |
| Runner | Pipe 不再传完整报告；改传小 manifest／安全本地对象句柄，上传流式分片；进程仍隔离，路径／内容 hash／预算必须验证 |
| 本地 spool | 加密 manifest 与分片引用；逐片持久化／确认，断点恢复不重算；保留当前 v1 spool 解密兼容 |
| Edge／D1／R2 | 新 artifact schema、stage 状态、分片 owner 校验与 finalize 原子提交；读取页只取需要分片，不每页解析整包 |
| 执行重放 | 验证完整 manifest、原 source config 与冻结数据根；按日期流式合并所有目标并执行，不能分片独立净值相加 |
| API／前端 | 轻量摘要／索引／分页；细节按需；明确完整实验、进行中和失败后可审计片段的区别；下载流式完整包 |
| 独立审计 | 能流式验证根与所有分片、全 origin 覆盖、全交易日台账、成交费用及 source/replay 同一身份，不只核对首页计数 |

压缩解决网络和磁盘成本，不能解决 Worker 解压／JSON.parse 的峰值内存，也不能解决客户端一次展开几十万行。完整 hash 的输入需要版本化；不能沿用旧 artifactId，却删除或挪走它原来覆盖的正文。

## 6. 自动验收门槛

所有门槛要写进下一轮执行计划并留机器可读证据；以下不是已经通过的测试清单。

1. **小池等价性**：使用固定 20／50 股 synthetic fixtures 与缺失、PIT、停牌样例，单体参考和分片实现输出相同 origin／目标／mask／模型选择、成熟时序与交易日台账。相同算法和固定数值环境优先要求字节一致；若合理浮点归约顺序改变，则提前声明容差，并承认新引擎版本／artifact 身份，不称原 hash 一致。
2. **拆分不变性**：随机改变块大小、任务顺序、worker 数与重试时机；同一计划结果不得改变。包含在块边界的 rolling(rank(...))、并列排名、跨片双标签、基线缺模型日期和 PCA refit。
3. **反未来扰动**：改变 cutoff 后价格、财务可用日或未来成员，cutoff 前目标、预处理、选择与预测保持不变。明示会影响已成熟之后的滚动再拟合，不错误要求整个终段模型永远不变化。
4. **完整性与所有权**：缺片、重片、乱序、错 hash、错计数、交叉 owner、篡改 sourceStrategy、仅主预测无基线、丢无效记录、模型／目标引用缺失均无法 finalize／execute。分页全部拼接等于完整 origin index；改变分页不能改变执行。
5. **故障恢复**：在读取、上传、D1 commit、claim ACK、结果 ACK 与取消各边界注入中断；恢复没有重复逻辑任务、重复账本或未知结果下的新 provider 采集；保留已确认字节，迟到 attempt 被 fence 拒绝。
6. **整池资源**：预声明 300 与 1000 个 synthetic 证券、5 年日历、32 特征、auto 8 候选、双基线、每日观察、固定折数和 refit。记录真实 CPU／wall／RSS／磁盘／完整产物字节／分片数；每次只有通过预声明预算才可标相应能力可用。另做高缺失／条件模型不可用场景，失败不能被成功子集掩盖。
7. **真实数据阶段**：仅在授权与账号能力确认后，冻结固定整池、固定区间、固定配置，一次采集后重复研究。检查完整日历、证券／成分范围、采集缺口、账单／请求尝试预算与结果。synthetic 通过不自动等于真实 provider 整池通过；负结果全部保留。
8. **组合一致性**：共享股票的多个篮子交叉重叠、同日排序并列、现金不足、T+1、锁盘、最低佣金和风险退出，在分片输入下与参考单一账户一致；factor exposure 仍是声明全池截面，不因持仓分片缩小分母。
9. **浏览器与下载**：固定首页／分页请求上限和浏览器内存预算，首屏不得下载全部预测；完整离线导出逐片校验成功，导出途中失败标明 incomplete；预览截断不冒充完整研究。
10. **准入拒绝**：超行数、特征内存、目标腿数、调用预算、候选次数、分片数或父 wall-clock 时，在相应边界明确失败；无静默抽样、无截断成功、无无限重试、无遗留运行子进程。

前端的容量证据应分别显示选中的完整成员数、实际有数据数、计划／已算／已验证／已提交分片数和缺失原因。一个 preview 的 `truncated:true` 表示只展示部分页面，与研究本身是否 complete 是两个不同维度；一个完成 900／1000 证券的任务不能被标成完整 1000 股研究。

## 7. 建议交付顺序

下一轮首先交付“分片完整产物＋数据快照＋流式审计”，在现有 50 股边界内验证恢复和数值等价；随后交付 300 股全池单资产预测／因子研究的真实容量 profile，再进入 1000 股及父子任务调度。大篮子、近似风险模型、更多候选和批量策略搜索各自单独验收。
