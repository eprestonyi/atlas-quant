# v0.10.0 — typed automatic factors and independent index inputs

Candidate only. The authenticated production baseline is v0.9.1 recorded in
`REBUILD_PLAN.md`; no v0.10 production change has been made.

Easy research chooses raw factors. The optional `auto-factor-preprocess/1`
contract freezes per-factor economic transforms and scope before estimator
selection. Training folds fit winsor limits, missing-value medians and median/IQR
scales. Asset statistics use training rows; a global input uses each training
date once. Compound DSL formulas retain their stated economic units. Existing
configurations omit this protocol and retain portable function v1 semantics.

Portable `atlas-model-function/2` keeps the exact construction, fold parameters,
estimator and numeric outputs. Reports lead with F in processed X coordinates;
each X expands into raw expression, economic transform and numerical processing.
A tree model remains a tree. Editing a function creates an unvalidated derivative.

Independent Tushare `index_daily` and `sw_daily` adapters use the 37 explicitly
registered index identities. Index history is not reconstructed from current
constituents. Prices, momentum, volatility, relative amount, valuation and stock
exposure expressions are definitions; neither their count nor unit tests prove
historical coverage, predictive edge or strategy profitability. The index source
root enters the frozen input identity, including dates when every output stock
lacks prices. Prices and labels remain missing on those dates.

Easy hides basket construction parameters and enforces all prerequisite steps
before navigation. Exactly two selected pool members can define a pair; larger
pools require two explicit objects, never arbitrary first-two sampling. Filter
resolution consumes pending text even without a browser change event.

Release requires:

1. Full Python/Node checks, cross-runtime true-fit golden vectors, replay/archive
   integrity and real browser steps on an isolated local server. Existing legacy
   artifacts remain unchanged.
2. Exact candidate CI and frozen source. Read current Worker/Portal bytes,
   bindings, queues, active leases, runtime trees and pending spools; back up the
   current baseline before mutation. Do not reuse old release/resume drivers.
3. Install the compatible Python build before new admissions. Both job enqueue
   and durable claim require explicit preprocessing and index-source capabilities;
   a version string is insufficient. Existing dataset/market profiles do not yet
   admit this new automatic protocol. Keep their existing release flags closed.
4. Extend only the private Portal provider allowlist for the registered index
   identities. Preserve original Portal code and bindings. Publish Worker and
   additive MKT field rows from the same frozen catalog. Read bytes/state back.
5. A new, bounded index data acceptance may verify exact source permission and
   history. Never replay previous financial provider or F canaries. An ambiguous
   upstream or mutation outcome requires readback before retry.
6. Publish source/tag with actual release receipts and browser evidence. No
   strategy, execution instrument or validated-alpha claim is part of this cycle.
